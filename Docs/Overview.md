The objective of this project is to learn model training with a real-world scenario.  Overall methodology and decisions made will be documented along the way.

## Objective

Using box score data and player ratings from 2024, predict outcomes of the 2025 season. 

Primary prediction targets:

- Home score (regression)
- Away score (regression)

Secondary derived targets:

- Win/Loss (classification from predicted scores)
- Point spread and total points (useful for calibration checks)

## Premise

Box scores provide a complete description of a game. Home vs Away, Players, Refs, Coaches, Weather, etc. If we can assemble enough objective, or trusted subjective, information as features that affect the labels (home score, away score) then we should be able to do a reasonably good job of predicting scores of games. Training a model should learn how much of each of these features affects the outcome. We cannot expect to predict subjective features (rivalry, internal locker room issues, etc) or luck.

## Methodology

- Assemble Training Data
- Define Features and Targets
- Split Data (time-aware)
- Train Baselines
- Train Candidate Models
- Evaluate and Diagnose Errors
- Freeze Best Model and Feature Schema
- Test Against 2025 Data

### Assemble Data

There are two csv files in the Data directory.

|File|Description|
|----|-----------|
|box_scores_2024.csv|This file was generated by scraping an NFL reference site. Meta data for each game of the season exists, including positional information|
|maddennfl24fullplayerratings.csv|Trusted player-ratings source used for feature engineering. While the original provider may change later, this schema is treated as a core input shape for roster-level ratings.|

This data needs to be merged into a new file that makes up the training data. The first step is to define the features and labels for the set.

Note that we will need to be able to provide the same shape and format of features for a working model to use new data. Document this shape thoroughly.

### Data Quality and Provenance

- Confirm key identifiers used for joins (team, player, game date, week, season).
- Validate that each game has exactly one home and one away record in the final table.
- Record missingness by column and decide one strategy per column family:
	- Numeric: median/mean imputation or explicit missing indicator.
	- Categorical: "Unknown" bucket.
- Keep a data dictionary with:
	- Column name
	- Type
	- Source file
	- Description
	- Allowed values/range
- Treat the player-ratings file as trusted for feature development, and keep the schema stable so alternative providers can be mapped into the same shape if needed.

### Define Features and Labels

Labels:

- `home_score`
- `away_score`

Candidate feature groups:

- Game context: home/away, week, rest days, weather, stadium type.
- Team strength signals: prior performance aggregates, rolling averages.
- Personnel quality: aggregated player ratings by projected starters/position groups.
- Coaching and officiating signals when available.

Important anti-leakage rule:

- Use only information that is known before kickoff for each game being predicted.
- Do not include final-game stats from the same game as input features.

### Split Strategy (Time-Aware)

Random splits can leak future information in sports prediction. Use chronological splits.

Suggested split:

- Train: earlier part of 2024 season
- Validation: later part of 2024 season
- Test: full 2025 season holdout

If enough data is available, use rolling/expanding window validation:

- Train on Weeks 1..k, validate on Week k+1, repeat.

### Baseline Models

Always establish simple baselines first.

- Baseline 1: predict average home and away scores.
- Baseline 2: team-level moving average scores (offense and defense).
- Baseline 3: linear regression using core features.

If advanced models cannot beat these baselines, revisit features and leakage assumptions.

### Candidate Models

Model ladder (simple to complex):

- Linear Regression / Ridge / Lasso
- Random Forest Regressor
- Gradient Boosted Trees (XGBoost/LightGBM/CatBoost)

Train two regressors (home, away) or a multi-output regressor. Compare both approaches.

### Evaluation Plan

Primary regression metrics:

- MAE (most interpretable in points)
- RMSE (penalizes large misses)

Derived classification metrics for winner prediction:

- Accuracy
- F1 (if class imbalance appears)

Calibration checks:

- Predicted vs actual score distribution
- Error by week, team, and home/away split

### Error Analysis and Diagnostics

- Analyze worst 20 prediction misses and tag likely causes (injury shocks, weather shifts, etc).
- Track whether errors cluster around specific teams or weeks.
- Compare early-season vs late-season performance.
- Check feature importances or SHAP values for reasonableness.

### Reproducibility and Experiment Tracking

- Fix random seeds where applicable.
- Save train/validation/test split definitions.
- Version datasets used for each run.
- Log each experiment with:
	- Feature set version
	- Model type and hyperparameters
	- Metrics on validation and test
	- Notes on failures/surprises

### Production Readiness Checklist

Before testing on 2025 data:

- Freeze final feature schema and preprocessing pipeline.
- Confirm new data can be transformed into identical model input shape.
- Validate no training-only columns are required at inference time.
- Save model artifact and preprocessing artifact together.
